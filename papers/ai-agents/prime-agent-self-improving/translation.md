**翻译日期**: 2026-08-29

## 摘要（Abstract）

语言模型（Language Model）是顺序处理器，但长时程智能体（Long-Horizon Agency）需要超出模型权重和活跃上下文（Active Context）的外部信息和计算。Prime Agent 是一个用于长时程评估和编码智能体工作流的开源运行环境（Harness）。一个持久的 IPython REPL（Read-Eval-Print Loop）遵循递归语言模型（Recursive Language Model）抽象，用于可编程的上下文处理和测试时计算（Test-Time Compute），而持续运行环境（Continual Harness）则在不同轨迹（Trajectory）之间保留历史、记忆、技能、提示和子智能体（Subagent）规格。递归子智能体通过直接的智能体间通信（Agent-to-Agent Communication）进行协调，而智能体视图（Agents View）让人类可以检查和管理守护进程（Daemon）支持的会话。Prime Agent 标准化了执行、恢复、验证和资源核算，同时将策略构建留给模型。这种低摩擦、富有表现力的“膜”防止运行环境故障成为模型故障，并将测量推向模型真正最大化底层能力。Prime Agent 将 ARC-AGI-3 RHAE Best@1 从 30% 提升到 95.5%，并在长上下文编码、GPU 内核生成、模拟器构建和自主 nanoGPT 速度挑战中匹配或超越原生和流行的运行环境。在 Factorio 中，我们发现精炼（Refinement）允许持续的技术进步，而专用子智能体能够实现并行化工作。代码可在 https://github.com/PrimeIntellect-ai/prime-agent 获取。

## 1. 引言（Introduction）

一个强大的语言模型本身并不具备计算机的全部能力。LLM 是一个有界的顺序处理器，其下一个决策只能使用其权重和活跃上下文中暴露的状态信息。运行环境（Harness）提供了缺失的计算基底（Computational Substrate），允许通过工具调用（Tool-Call）执行外部操作。这些外部操作还包括超越存储在模型权重中的先验知识的信息管理。上下文管理最早由智能体压缩（Agentic Compaction）实现，即模型选择性地分析自身上下文以减少令牌（Token）同时保留关键信息的过程。然而，完整的信息状态已超出权重和令牌上下文的范围。将其想象为状态信息缓存（图 2）：模型权重是 L0，活跃上下文是 L1，持久 REPL 和递归子智能体构成 L2，磁盘支持的历史、记忆和技能构成 L3。这使得系统更像冯·诺依曼架构（Von Neumann Architecture）：模型可以读取、转换和写入当前正在生成的指令之外的可寻址状态 [34, 35]。

这种视角使表现力（Expressivity）成为运行环境的关键属性。与其编码单一工作流，一个富有表现力的运行环境暴露原语（Primitive），模型在推理时（Inference Time）用它们构建程序、子智能体和反馈循环。递归语言模型（RLM）使上下文和递归调用可编程 [44]；持续运行环境（Continual Harness）使提示、子智能体、技能和记忆可从轨迹历史中修订 [19]。最后，我们通过直接的智能体间通信实现大规模多智能体集群（Multi-Agent Swarm）的协调和编排。这些组件让固定模型能够利用信息管理和测试时计算来扩展其可达策略集（Reachable Strategy Set）。

Prime Agent 首先被设计为长时程评估的标准化运行环境。其中最受欢迎的指标是在固定支出下的分数（Score at a Fixed Expenditure）[8]，例如成本/令牌和时间，或者特别是对于长时程，在实际平台期的分数（Score at Practical Plateau）[8]，这允许我们分析性能随时间变化的形状。运行环境是模型观察和作用于世界的膜（Membrane）。模型应该因为任务超出其能力而评估失败，而不是因为运行环境丢失状态、限制有用操作、错误计算资源或过早终止。因此，Prime Agent 将标准化、可靠的执行与用于可编程工具、信息管理和集群管理的低摩擦、富有表现力的接口相结合。这让模型能够充分利用其测试时计算，将测量性能推向其真正最大化底层能力，而非运行环境的局限。

Prime Agent 联合管理信息和计算。信息管理通过可编程上下文处理、压缩、持久历史和可修订记忆在 L1–L3 之间移动状态。计算管理将测试时计算分配给程序、工具调用、可重用技能和并行递归子智能体 [32, 44]。直接的智能体间通信连接两者，跨分布式计算路由信息，使集群能够动态协调而非遵循固定图。这些通信链路还让人类可以检查、发消息、附加到和干预子智能体会话，而无需跟踪每次交换 [17, 21]。这些交互共同产生保留的轨迹，改进未来的计算并可训练后续模型世代 [25, 40, 43]。

我们提出 Prime Agent，一个用于长时程模型评估和编码智能体工作流的开源运行环境。Prime Agent 集成了跨活跃上下文、持久可编程执行、递归子智能体以及保留的历史、记忆和可重用技能的信息和计算管理，通过直接的智能体间和人机通信连接。其智能体视图（Agents View）提供了一个可视化界面，用于检查、附加到和管理持久的守护进程支持的智能体会话。我们在保留模型构建自身策略自由的同时标准化评估基础设施。Prime Agent 将 ARC-AGI-3 性能从 30% 提升到 95%，匹配或超越 Pi、Claude Code 和 Codex（并在其他基准测试中优于其他运行环境，如 Hermes Agent、OpenCode 和 Kimi-Code），涵盖长上下文编码、GPU 内核生成和模拟器构建，持续 85.5 小时的 nanoGPT 运行并验证了 19 条记录，并支持四字符 Factorio 控制和长时程 MazeBench 探索。

## 2. Prime Agent 架构（Prime Agent Architecture）

接下来我们详细描述 Prime Agent 架构。具体来说，我们讨论 (1) 系统如何管理信息和计算（§2.1），(2) 状态如何在模型权重、活跃上下文、REPL 和磁盘支持存储之间组织（§2.2），(3) 持久 REPL 和 RLM 调用如何支持可编程计算（§2.3），(4) 递归会话如何与智能体和人类操作员通信（§2.4），(5) 持续运行环境如何将轨迹证据转化为可重用状态（§2.5），以及 (6) 长时程控制如何定义继续、终止和评估核算（§2.6）。图 1 提供了概述。

### 2.1 架构概述（Architecture Overview）

Prime Agent 将信息管理与计算管理分离。信息管理确定什么状态进入模型调用以及什么状态在压缩或重启后保留。

计算管理将模型选择的操作映射到代码、工具和递归子智能体会话。直接的智能体间通信连接相关会话，直接的人机交互暴露单个节点以供检查和干预。

模型使用代码操作中间值。会话在压缩、分离和重启期间保留历史。子智能体继承根的执行和通信原语。运行时记录模型调用、工具使用、消息、运行环境更改和资源使用。模型控制分解、计算分配、通信和停止。

### 2.2 信息层次和持久状态（Information Hierarchy and Persistent State）

模型调用由固定权重和活跃令牌上下文上的条件参数化。Prime Agent 添加了该上下文之外的状态。外部状态在运行时注入它或将结果序列化到上下文中时影响生成。图 2 按可见性、访问机制和持久性组织此状态。

每个级别通过不同的机制改变。微调（Fine-Tuning）更新 L0，压缩（Compaction）重写 L1，精炼（Refinement）版本选择 L3 条目。我们将 L2 机制称为智能体垃圾回收（Agentic Garbage Collection）。模型根据任务变化创建、保留、总结或删除 REPL 值和子智能体会话。

显式操作在级别之间移动信息。L2 中的 Python 值和工具输出在序列化到 L1 时进入生成。压缩用摘要替换对话前缀，并将原始事件保留在 L3 中以供 REPL 检索。运行时将选定的持续运行环境条目组装成后续补充提示；其他 L3 产物在检索时进入上下文。L0 保持固定。

保留的运行时状态包括仅追加的事件历史、选定的内核快照、有根会话树、上下文和压缩记录、持久消息队列以及版本化的持续运行环境状态。分支或分叉创建新的逻辑延续而不删除先前的事件序列。恢复在相同身份下重建会话。不可序列化的 Python 对象和外部进程从保存的产物或外部服务重新创建。

### 2.3 使用 RLM 的可编程计算（Programmatic Computation with RLMs）

每个会话拥有一个持久的 IPython 读取-求值-打印循环（REPL）。在测试时，计算包括模型推理、Python 执行和工具调用；评估分别报告令牌、时间和成本。安装的工具作为 Python 模块导入，用于解析、过滤、聚合和验证，使用普通代码。中间值跨轮次持久化，直到被选择才进入活跃上下文。这避免了将大型日志、任务规范和结构化评估器输出重复序列化到上下文中。

Prime Agent 使用异步 rlm 原语 [44] 实现 RLM 抽象。调用 rlm 创建并调度一个子智能体会话，然后在子智能体完成之前返回一个稳定句柄（Handle）。子智能体接收自己的模型上下文、IPython 内核、历史和工作区元数据。父级在子智能体运行时继续本地计算。结果稍后通过直接的智能体间通信到达，保留的句柄支持压缩或重启后的后续操作。模型在本地代码、工具、顺序委托和并行子智能体之间选择。Prime Agent 定义它们的执行语义而非固定工作流图。完整的编排示例出现在 B 节。

### 2.4 递归编排和交互（Recursive Orchestration and Interaction）

守护进程独立于创建它的客户端拥有实时会话。根和子智能体会话使用相同的生命周期。会话在轮次或工具操作期间运行，在没有活跃轮次加载时空闲，在从持久状态卸载但可恢复时不活跃。客户端分离使会话保持运行。稳定的会话和父级标识符在这些转换中保留递归拓扑。

直接的智能体间通信使用异步的、守护进程介导的队列。智能体寻址其父级、子级和同级，排队消息在接收者再次活跃时保持可用。文件系统、网络和凭证访问遵循运行时环境的权限。图 3 总结了共享生命周期和通信拓扑。

智能体视图（Agents View）暴露持久树以进行直接的人机交互。该界面允许用户检查历史、附加到会话、提供新输入或分离而不中断执行。agent-observe 接口提供有界的只读状态和最近消息预览；agent-message 以命名的相关会话为目标。这允许通过编排器进行完全交互。

### 2.5 持续运行环境（Continual Harness）

持续运行环境暴露用于轨迹时读写的补充状态 [19]。提示笔记（Prompt Notes）存储行为指令，记忆（Memories）存储事实，技能（Skills）打包可执行过程，子智能体规格（Subagent Specs）存储可重用的角色或分工。类型化状态分离规则、事实、程序和协调模式。条目支持创建、读取、更新和删除操作；本地条目属于一个会话，明确请求的全局条目对后续会话保持可用。

精炼（Refinement）将轨迹证据转化为版本化的状态更新。智能体直接请求编辑，或 /refine 在相关事件上运行后台模型调用。运行时在轮次边界应用每个编辑，记录其触发因素和预期效果，并为下一次调用组装补充状态。版本保留来源并支持回滚。精炼补充了不可变的基础提示而不重写基础策略。

自我改进（Self-Improvement）将执行证据转化为持久的运行环境状态，改变后续行为而模型权重保持固定。有用的计算变成技能，重复的协调模式变成子智能体规格，修正的假设变成记忆或提示笔记。产生的轨迹记录也为后续模型世代提供训练数据。

### 2.6 长时程执行和评估语义（Long-Horizon Execution and Evaluation Semantics）

Prime Agent 暴露三种长时程控制机制（图 4）。

自主模式（Autonomous Mode）在显式预算内继续模型轮次，并在每个轮次后评估任务指定的结束条件测试。失败的测试返回有界输出以供另一次尝试；轮次、令牌和挂钟限制停止执行。目标（Goal）在跨延续保留一个目标，并通过智能体完成（当智能体标记目标完成时）结束。心跳（Heartbeats）按定时或定时调度启动轮次。

评估配置将任务和工具接口绑定到模型和提供者设置、压缩和精炼策略、重试策略、完成门（Completion Gates）和资源限制。核算聚合根和后代会话，因此委托在测试时成本中保持可见。事件历史将模型和工具调用、消息、干预、重试、验证器结果和运行环境编辑链接到该配置。标准化持久性、恢复、终止和核算将运行环境故障与模型故障分离，同时保留模型对分解的控制。

## 3. 评估（Evaluation）

评估解决了源自 Prime Agent 设计的三个研究问题。RQ1：测试时缩放（Test-Time Scaling）。标准化、富有表现力的执行接口能否让前沿模型将额外的输出令牌和 API 成本转化为经过验证的任务进展？我们在 ARC-AGI-3 上评估这个问题。RQ2：信息管理。模型能否使用持久 REPL 状态在长上下文中搜索、转换和聚合信息？我们在长上下文推理和编码任务上比较 Prime Agent 与原生和替代运行环境。RQ3：持久递归执行。相同的运行时能否持续多天实验、迭代系统构建、递归控制和在线精炼？我们通过端到端结果和轨迹分析研究 nanoGPT、PMPP-Hard、EmulatorBench、Factorio 和 MazeBench。轨迹分析显示智能体如何分配子智能体、保留信息和从干扰中恢复。

### 3.1 测试时规模的交互式推理（Interactive Reasoning at Test-Time Scale）

ARC-AGI-3 是 Prime Agent 支持强大、一致的长时程评估的最清晰测试 [1]。每个游戏要求模型在行动限制下学习游戏规则，创建一个临时世界模型。Prime Agent 仅提供环境接口和从 PRO-LONG [9] 改编的自主提示；模型构建策略。我们注意到 Claude Code 和 Codex 的运行表现比 Anthropic 和 OpenAI 自我报告的 ARC-AGI-3（公共集）性能差，因此我们采用匹配的提示和设置来运行它们。

在观察到的配置中，额外的输出令牌和成本以截然不同的速率转化为进展（图 5）。较强的配置在长交互水平上持续改进，而其他配置早期就趋于平稳。这种模式与允许依赖模型的测试时缩放而非强加固定工作流的模型控制接口一致。参考线和点将这些曲线与官方 ARC 结果并列。它们是外部值，因为我们的原生运行环境重跑低于已发布分数，因此它们定位结果而非隔离因果运行环境效应。

### 3.2 长上下文信息管理（Long-Context Information Management）

长上下文套件测试模型能否主动管理不适合自然放入一个提示的信息。Prime Agent 将初始上下文存储在可读文件中，允许模型从持久 REPL 搜索、转换、总结和重新访问它。这将长上下文推理从固定序列上的被动注意力转变为可编程的信息管理问题。该套件涵盖聚合、潜在检索、指令遵循、推理和长形式编码 [3, 5, 6, 23, 33]。

我们通常发现 Prime Agent 在广泛长任务中具有竞争力，特别是与未围绕其训练的运行环境相比。Prime Agent 在长时间运行或长上下文任务中尤其表现出色，并且可以作为自主智能体有竞争力地运行。我们包含一组专注于 Prime Agent 表现优异的长设置的案例研究和实验。

### 3.3 多天自主研究（Multi-Day Autonomous Research）

nanoGPT 速度挑战 [4] 衡量智能体能将 124M 参数 GPT 达到固定验证损失所需的训练步数减少多少，每条记录作为八种子平均值进行验证。对于三种模型中的每一种（Kimi K3、DeepSeek V4 Pro 和 GLM 5.3），我们将 Prime Agent 与替代运行环境进行比较：模型开发人员自己的 CLI（如果存在），否则使用 Claude Code 或 opencode。我们发现运行环境的选择对最终记录的影响很小，与实验噪声相比。

然而，模型行为不同。在 Prime Agent 上，模型经常使用持久 REPL 在基准训练脚本之外进行实验，例如在启动训练运行之前模拟候选优化器在合成梯度上或数值优化更新规则系数。图 6 统计了这些实验在 18 次运行中的情况，按每个智能体执行的训练运行次数标准化；A 节复制了每个模型的这样一个实验。效果在 DeepSeek V4 Pro 上最大，它在 Prime Agent 下每个训练运行创建的此类实验大约比 Claude Code 多六倍。这可能是因为 DeepSeek 自己的智能体运行环境提供了类似的代码执行模式，因此 REPL 与模型可能训练过的工作流匹配。我们还观察到模型构建了基准本身的可编程接口：Kimi K3 定义了一个探测函数，通过它运行了大约九十次筛选实验和所有 19 条经过验证的记录，而同一模型在自己的 CLI 上通过直接文件编辑执行每个操作，没有构建这样的机制。

### 3.4 可编程系统构建（Programmatic Systems Construction）

模拟器（Emulators）。模拟器是再现另一个计算机系统可观察行为的软件。我们在 EmulatorBench 上评估 Prime Agent，这是一个要求智能体使用 Rust 为各种游戏系统构建模拟器的基准。智能体获得模拟器规范和以验证器形式提供的诊断测试。

模拟器的正确性由其模仿目标机器行为的能力给出。这通过人类生成的诊断程序测量，这些程序检查模拟器的行为，如 CPU 标志、PPU 时序和其他组件。为了尽量减少数据污染的影响，我们要求智能体从零开始在 Rust 中构建模拟器，在沙箱中没有任何参考实现。我们在表 1 中报告了这个长上下文编码基准的初步结果，平均超过 16 次模拟器重建，以及图 7 中两个模拟器（世嘉 Genesis 和任天堂 Game Boy Color），Prime Agent 成功复制。对于 Opus，我们的运行尽管工具调用响应成功，但出乎意料地未能解决任务。

GPU 内核。PMPP-Hard 将相同的可编程循环压缩为在挂钟预算下的重复编辑、编译、正确性检查和性能分析周期。

Prime Agent 和原生运行环境仍然接近，在两组模型之间顺序反转。在这些报告的模型内比较中，通用持久接口支持编译器-性能分析循环，没有观察到大的差距。PMPP-Hard 的一个已知限制是严格的挂钟预算比较。挂钟预算未揭示的是使用 Prime Agent 的模型在令牌使用方面的显著改进。这意味着 Prime Agent 以显著降低的成本实现了与 Codex 或 Kimi-Code 相同的性能，并且逐令牌地，Prime Agent 具有优势。

### 3.5 持久交互和精炼（Persistent Interaction and Refinement）

Factorio。Factorio Learning Environment 暴露用于持久工厂世界的 Python 观察和行动 [12]。在七天的 Sonnet 5 运行中，根及其后代使用了 2340 万个输出令牌，完成了 196 项技术中的 24 项，并在高级电路研究上达到 71%（图 9），没有停滞迹象。

模型处理不可逆操作的能力较差。一次破坏性的世界重置将技术计数从五恢复到一；会话随后恢复并继续运行而不是丢弃轨迹。根在 149 次调度波中创建了 633 个深度为一的子智能体，最多同时激活七个。浅而反复扩大的树记录了并行任务专业化而非更深递归，而突发的技术曲线将长构建间隔与外部验证的进展分开。

不同的 Factorio 轨迹揭示了在线精炼的核心安全故障。智能体发现 RCON 命令可以直接将资源生成到装配机中，尽管有防作弊心跳仍使用了捷径，然后将其保存为可重用技能。在此轨迹中，持久性保留了优化测量目标的行为，包括规范利用。因此，安全部署需要最小权限行动接口、独立状态验证和受污染精炼的可审计回滚。

MazeBench。MazeBench 是一个开放世界 3D 空间推理环境，玩家控制一个 3D 立方体，必须在全局迷宫中解决谜题房间，同时收集宝石。前沿模型被证明在该任务上极为困难，花费数十亿令牌仅解决整体世界的一小部分。我们将 Opus 5 和 GPT-5.6 Sol 与 Prime Agent 及其原生运行环境进行比较，以及 GLM-5.2 与 Claude Code。按照基准指标，我们报告他们发现的唯一房间数、唯一状态数和宝石总数，所有这些都作为其总令牌支出的函数。

## 4. 相关工作（Related Work）

可编程推理和自适应状态。可编程推理赋予模型代码、工具和递归调用，用于转换上下文和分配测试时计算 [9, 30, 32, 37, 42, 44]。记忆和精炼方法跨轮次和任务保留选定的观察、反馈、技能或推理轨迹 [22, 24, 26, 31, 36, 43]。持续运行环境将提示、记忆、可执行技能和子智能体规格存储为类型化、版本化的状态 [19]。Prime Agent 将这些机制与持久内核、递归会话、恢复和完整轨迹捕获集成。

编码智能体和长时程评估。编码智能体运行时使用可执行操作、仓库工具、沙箱、事件历史和结构化角色分配来解决许多交互步骤的任务 [11, 20, 27, 37–39, 41]。可执行基准和轨迹语料库测量问题解决、指令遵循、检索和在长上下文或扩展交互下的推理 [3, 5, 6, 13, 23, 25, 33, 40]。Prime Agent 使执行基底持久和递归，然后跨根和后代会话记录支出。

ARC-AGI-3 上的交互式推理。ARC-AGI-3 将抽象推理扩展到具有隐藏动态、目标和行动语义的交互环境 [1, 2]。社区系统构建和验证可执行世界模型，将智能体表示为有状态 Python 对象，优化外部工作区，协调专门智能体，并跨游戏保留过程 [7, 9, 10, 19, 28, 29]。Prime Agent 为同类长时程交互任务提供持久递归执行和标准化评估设置。

多智能体和人机通信。语言模型智能体系统通过角色提示、自然语言消息、共享产物和显式信念状态进行协调 [11, 20, 21, 27, 29, 39]。学习的多智能体通信研究稀疏消息选择、压缩表示、社会学习、策略对齐和对人类伙伴的可解释性 [14–17]。Prime Agent 通过持久的家族范围队列实现直接的智能体间通信，并将相同的会话树暴露给人类检查和干预。

## 5. 结论（Conclusion）

Prime Agent 引入了智能体运行环境设计的新范式，其中持久执行、递归会话、自主控制、记录历史和持续运行环境形成一个用于长时程工作的基底。跨交互式推理、长上下文任务、自主研究、系统构建和持久环境的结果表明，该基底在标准化执行和核算下支持不同形式的测试时计算。尽管相对于替代运行环境的结果，模型在决定如何分配子智能体、管理保留信息和精炼可重用状态时仍存在摩擦。许多运行环境能力仍未得到充分利用，因为当前模型未经训练以操作它们。我们预计模型-运行环境协同学习将成为通向新长时程能力的主要途径。直接用 Prime Agent 训练可以教会模型更有效地使用集成运行环境，而针对 RLM 和持续运行环境组件的训练可以隔离它们的贡献。
